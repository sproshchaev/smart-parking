//      - List - только чтение, MutableList - с методами изменения
//      - Map, MutableMap

//      - buildList { ... } - фабричные функции вместо конструкторов

//    map    - превращает каждый элемент в другой  
//    count  - считает по условию
//    forEach - обход элементов
// 4) groupBy - превращает плоский список в Map<Ключ, List<Элемент>>
// 5) Сортировки: sortedBy - по одному ключу
//                sortedWith(compareBy(...)) - по нескольким подряд
// 6) Поиск: firstOrNull - первый подходящий элемент или пусто
//           first - бросает исключение, если не нашел
// 7) Pair - пара значений, создается через to или через конструктор. Применяется деструктуризация
// 8) it - единственный параметр лямбды по умолчанию, 
//         в forEach по карте параметров два, поэтому их называют явно: { (key, value) -> ... }

//   8) писать преобразование числовых типов явно: toInt и тд

// Теория (вебинар 9)
// 1) enum class - перечисление, константы (с полями и методами). Список доступен entries 
// 2) data class - класс-хранилище объектов (toString, equals & hashCode, copy, разложение на переменные)
// 3) Деструктуризация - val (a, b, c) = объект - разложение объекта по позициям свойств 
// 4) companion object -  объект-компаньон класса (в Java это статика: фабрики, константы), вызов Класс.метод().
// 5) sealed interface / sealed class - закрытая иерархия: все наследники известны, мы можем when исп без else  
// 6) data object -  вариант без собственных данных: экземпляр один на все приложение, и toString
// 7) when с аргументом и is - проверка типа с авто-приведением: внутри ветки объект уже нужного типа

// Лучшие практики
// 1) Рекомендуется делать данные неизменяемыми, все свойства Session - val. Измененная версия через copy (оригинал не затрагивает)
      Неизменяемый объект можно передавать как параметр (его не испортят) + многопоточка 
// 2) Не пишем equals & hashCode руками, используем data  
// 3) Рекомендуется давать перечислению собственные данные вместо паралельного when 
// 4) рекомендуется переходить с enum на sealed в случае если вариантам нужно разные данные
      enum - константы одного типа с одинаковым набором полей. У исходов набор будет разный: если номер распознан - то Session, если нет - то сырая строка (sealed) 
// 5) рекомендуется не писать else в when по закрытой иерархии. Ветка else снижает пользу sealed 
// 6) Рекомендуется сохранять исходное значение вместе с ошибкой UnknownPlate(val raw:String?) 
// 7) Рекомендуется прятать сборку объекта в фабрику
// 8) Рекомендуется использовать data object для варианта без данных. "Места нет" - всегда одно и то же сообщение (экземпляр на каждый отказ избыточен, используем toString)

// 2) val x: String? = "..."
// 3) Безопасный вызов ?.

// 5) (?. и ?) vs ручные проверки: raw?.trim()?.uppercase() vs (3 x if)
